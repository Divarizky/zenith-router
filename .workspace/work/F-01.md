# F-01 — Base Gateway & Core Translator

## Problem
Coding agent seperti Pi, Claude Code, Cursor, dan Codex mengirimkan payload dalam format wire yang berbeda (OpenAI Chat Completions, Anthropic Messages API, atau Codex Responses API). Pengembang membutuhkan satu gateway lokal ultra-ringan tanpa dependensi berat yang mampu menerima format tersebut, mendeteksi target model/provider, menerjemahkan format request dan response secara transparan, serta mendukung streaming SSE dengan latensi mendekati nol.

## Solution
zenroute menyediakan endpoint `/v1/chat/completions`, `/v1/messages`, `/v1/responses`, dan `/v1/models` berbasis Hono. Sistem mengimplementasikan Hub-and-Spoke translator menggunakan format OpenAI sebagai pivot tengah untuk mengonversi request dari klien ke format target provider dan sebaliknya, baik untuk streaming Server-Sent Events (SSE) maupun respon non-streaming.

## User Stories
- (MUST) As a developer using Pi or Cursor, I want to send OpenAI-compatible requests to `/v1/chat/completions`, so that I can interact with any configured model seamlessly.
- (MUST) As a developer using Claude Code, I want to send Anthropic-compatible requests to `/v1/messages`, so that Claude Code can operate without client-side modifications.
- (MUST) As a developer, I want streaming responses (SSE) to be relayed chunk-by-chunk with zero artificial delay, so that agent generation feels responsive.
- (MUST) As a developer, I want to query `/v1/models` to discover all available routed models and combos.
- (SHOULD) As a developer, I want upstream transport errors (429, 5xx) that occur prior to first byte emission to be caught cleanly, so that failover can be triggered safely.
- (NICE) As a developer, I want warmup and naming requests from tools like Claude Code to be answered locally without hitting upstream providers, so that token usage is saved.

## Acceptance Criteria
- AC-01: WHEN client mengirim request `POST /v1/chat/completions` THEN sistem SHALL memproses request dalam format OpenAI dan mengembalikan respons OpenAI yang valid.
- AC-02: WHEN client mengirim request `POST /v1/messages` THEN sistem SHALL memproses request dalam format Anthropic dan mengembalikan respons Anthropic yang valid.
- AC-03: WHEN format klien berbeda dari format provider upstream THEN sistem SHALL menerjemahkan payload melalui pivot format OpenAI sebelum dikirim ke upstream.
- AC-04: WHILE streaming diaktifkan (`stream: true`) THEN sistem SHALL mengalirkan Server-Sent Events (SSE) langsung ke client menggunakan native TransformStream tanpa buffer penuh.
- AC-05: WHEN client mengirim `GET /v1/models` THEN sistem SHALL mengembalikan daftar model aktif dalam format skema OpenAI Model List.
- AC-06: IF body request tidak valid atau model tidak terdaftar THEN sistem SHALL mengembalikan status HTTP 400 atau 404 dengan format error standar OpenAI.
- AC-07: IF upstream provider mengalami kegagalan sebelum byte respons pertama dikirim THEN sistem SHALL mengembalikan status error yang sesuai tanpa membiarkan koneksi menggantung.
- AC-08: WHERE request terdeteksi sebagai prompt warmup atau model naming Claude Code THEN sistem SHALL mengembalikan respons instan sintetis tanpa memanggil provider upstream.

## Implementation Decisions
**Final**:
- Menggunakan standar native Web API `Request`, `Response`, `ReadableStream`, dan `TransformStream` tanpa middleware stream pihak ketiga.
- Format pivot tengah untuk translasi adalah format OpenAI Chat Completions standar.
- Endpoint handler menerima raw `Request` dari context Hono (`c.req.raw`) agar decoupled dari framework.

**Open**:
- Penanganan format multipart/image pada pesan input — apakah ditranslasikan penuh atau difilter pada tahap awal.
- Penanganan format reasoning/thinking token (`reasoning_content`) pada model hybrid.

## Testing Decisions
- **Seam(s)**:
  1. `src/translator/index.js` — Function `translateRequest(sourceFormat, targetFormat, body, stream)`: Seam isolasi translasi payload.
  2. `src/executors/base.js` — Class `BaseExecutor` dengan method `execute(options)`: Seam abstraksi transport jaringan (mudah di-mock).
  3. `src/gateway/chat.js` — Controller `handleChat(request)`: Seam integrasi HTTP level endpoint.
- **Test Strategy**:
  - Unit tests untuk translasi format (OpenAI ↔ Claude ↔ Gemini) dengan payload mock.
  - Integration tests untuk endpoint `/v1/chat/completions` dan `/v1/messages` menggunakan mock executor.
- **Environment**: Node.js 22+ local test harness.

## Out of Scope
- Alur login OAuth dan refresh token background (bagian dari F-02).
- Tracking akumulasi token ke database SQLite (bagian dari F-03).
- Optimasi pemadatan prompt token RTK dan Caveman (bagian dari F-04).
- Antarmuka web dashboard (bagian dari F-05).
