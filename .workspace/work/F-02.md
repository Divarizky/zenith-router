# F-02 — Provider Connections & OAuth

## Problem
Pengguna memiliki banyak kredensial akun untuk provider AI (API Key dan akun OAuth dari Claude, Codex, GitHub Copilot, GLM, dll.) yang sering kedaluwarsa atau terkena limit rate. Tanpa sistem penyimpanan lokal dan manajemen token refresh otomatis, pengguna harus memperbarui kredensial secara manual atau mengalami gangguan saat coding agent bekerja. Selain itu, beberapa koneksi memerlukan proxy jaringan khusus untuk mengakses upstream.

## Solution
zenroute menyediakan layer persistensi akun berbasis `node:sqlite` untuk menyimpan kredensial koneksi (API Key dan OAuth tokens) secara aman dan lokal. Sistem menyediakan alur autentikasi OAuth, rotasi otomatis akun saat rate limit terjadi (`cooldown_until`), refresh token otomatis sebelum kedaluwarsa atau saat upstream mengembalikan HTTP 401, serta dukungan konfigurasi proxy per koneksi.

## User Stories
- (MUST) As a developer, I want to store API keys and OAuth credentials in a local SQLite database, so that my credentials persist across server restarts.
- (MUST) As a developer, I want the system to automatically refresh expired OAuth access tokens, so that my coding sessions are not interrupted by token expiry.
- (MUST) As a developer, I want to associate a specific proxy URL with an individual connection, so that requests for geo-restricted providers are routed through the proxy.
- (SHOULD) As a developer, I want an account to be temporarily locked with a cooldown when it hits a 429 rate limit, so that the router seamlessly picks the next available account.
- (NICE) As a developer, I want a background refresh loop to proactively renew OAuth tokens that are within 5 minutes of expiring.

## Acceptance Criteria
- AC-01: WHEN sistem diinisialisasi THEN database SQLite `data/zenroute.db` SHALL dibuat dengan tabel `connections` dan indeks yang sesuai jika belum ada.
- AC-02: WHEN client mengirim request API ke provider THEN sistem SHALL mengambil connection aktif yang tersedia dengan metode prioritas atau rotasi yang tidak sedang dalam masa cooldown.
- AC-03: IF access token suatu connection telah expired THEN sistem SHALL memperbarui token menggunakan refresh token yang tersimpan sebelum mengirim request ke upstream.
- AC-04: IF upstream mengembalikan status HTTP 401 atau 403 THEN sistem SHALL mencoba melakukan refresh token satu kali dan mengulang eksekusi request ke upstream.
- AC-05: IF upstream mengembalikan status HTTP 429 THEN sistem SHALL menandai connection tersebut dengan status cooldown sementara (`cooldown_until`).
- AC-06: WHERE connection memiliki konfigurasi `proxy_url` THEN sistem SHALL meneruskan request ke upstream melalui proxy tersebut.
- AC-07: WHEN connection baru didaftarkan (API Key atau OAuth) THEN sistem SHALL memvalidasi skema field dan menyimpannya sebagai record aktif.
- AC-08: WHILE loop background refresh berjalan THEN sistem SHALL memindai dan memperbarui semua token OAuth yang mendekati waktu kedaluwarsa (< 5 menit).

## Implementation Decisions
**Final**:
- Menggunakan `node:sqlite` (`DatabaseSync` bawaan Node 22+) untuk tabel `connections` tanpa library ORM eksternal.
- Secret credentials disimpan terisolasi di file SQLite lokal `data/zenroute.db` dan dilarang dikomit ke git.
- Konfigurasi proxy terintegrasi langsung pada record connection (`proxy_url`), bukan di pool terpisah.

**Open**:
- Algoritma enkripsi at-rest untuk token OAuth (apakah plaintext local DB cukup untuk personal use, atau perlu AES-256-GCM opsional dengan master key).
- Mekanisme interaksi browser untuk initial OAuth login (CLI URL polling vs loopback redirect).

## Testing Decisions
- **Seam(s)**:
  1. `src/db/index.js` — Interface eksekusi query SQLite lokal.
  2. `src/services/auth.js` — Fungsi `getConnection(provider)` dan `markConnectionCooldown(id, durationMs)`.
  3. `src/services/tokenRefresh.js` — Fungsi `refreshOAuthToken(connection)`.
- **Test Strategy**:
  - In-memory SQLite database (`:memory:`) untuk testing isolasi tanpa menyentuh disk.
  - Mock OAuth endpoint untuk menguji skenario token refresh kadaluarsa dan penanganan error 401.
- **Environment**: Node.js 22+ local test harness.

## Out of Scope
- Pencatatan log penggunaan token per request (bagian dari F-03).
- Antarmuka UI form penambahan koneksi (bagian dari F-05).
- Algoritma kompresi token RTK (bagian dari F-04).
