# F-03 — Usage Tracking & Quota Sync

## Problem
Pengguna mengintegrasikan beberapa provider AI dan akun yang memiliki batas kuota dan biaya berbeda. Tanpa pencatatan metrik penggunaan lokal dan pemantauan sisa kuota live, pengguna tidak dapat mengetahui berapa banyak token yang dikonsumsi oleh agent coding (seperti Pi atau Claude Code) atau kapan kuota suatu akun akan habis sebelum terjadi kegagalan request.

## Solution
zenroute menyediakan modul pencatatan konsumsi token dan sinkronisasi kuota. Setiap respon chat (baik non-streaming maupun streaming SSE) disadap secara non-blocking untuk mengekstrak metrik token (`input_tokens`, `output_tokens`, `duration_ms`) dan menyimpannya ke tabel `usage_history` di SQLite. Selain itu, sistem menyediakan sinkronisasi sisa kuota live untuk provider yang menyediakan endpoint telemetri/saldo.

## User Stories
- (MUST) As a developer, I want token consumption (prompt and completion tokens) from every chat request to be recorded in SQLite, so that I have a local audit trail of token consumption.
- (MUST) As a developer, I want streaming responses to report and persist final token counts when the stream completes without interrupting the real-time stream flow.
- (MUST) As a developer, I want an API endpoint `GET /api/usage` to query aggregated token statistics by day, provider, or model.
- (SHOULD) As a developer, I want the system to fetch and cache live remaining quota or subscription limits for supported providers.
- (NICE) As a developer, I want requests that did not consume tokens or failed before upstream response to be flagged with zero output tokens and error indicators.

## Acceptance Criteria
- AC-01: WHEN non-streaming chat request selesai THEN sistem SHALL mengekstrak objek `usage` dari respons dan menyimpannya ke tabel `usage_history` dengan ID koneksi, nama model, dan durasi request.
- AC-02: WHILE streaming SSE berlangsung THEN sistem SHALL menangkap event usage delta atau event penutup (`message_delta` / chunk usage) dan menyimpan total token ke `usage_history` saat stream ditutup tanpa memblokir transmisi data ke client.
- AC-03: WHEN client meminta `GET /api/usage` THEN sistem SHALL mengembalikan agregasi total `input_tokens`, `output_tokens`, dan `total_tokens` yang dapat difilter berdasarkan rentang waktu atau provider.
- AC-04: WHEN client meminta `GET /api/quota` atau detail koneksi THEN sistem SHALL mengembalikan informasi sisa kuota/saldo yang tersimpan di cache.
- AC-05: IF provider mendukung endpoint pengecekan saldo/kuota THEN sistem SHALL menyediakan fungsi sinkronisasi kuota live yang memperbarui status kuota pada koneksi terkait.
- AC-06: IF proses pencatatan usage ke database mengalami kendala THEN sistem SHALL tidak menggagalkan pengiriman respons utama ke client coding agent.
- AC-07: WHEN kuota atau saldo akun terdeteksi habis (0 token tersisa) THEN sistem SHALL menandai koneksi tersebut agar dilewati oleh credential resolver.

## Implementation Decisions
**Final**:
- Pencatatan usage dilakukan secara asynchronous (fire-and-forget setelah response selesai) agar tidak menambah latensi pada jalur kritis streaming LLM.
- Ekstraksi token streaming SSE memanfaatkan transformer tap pada `TransformStream` tanpa menduplikasi buffer stream penuh di memori.
- Menyediakan endpoint internal `/api/usage` dan `/api/quota` untuk konsumsi dashboard dan client control plane.

**Open**:
- Mekanisme penghitungan token estimasi (heuristik tokenizer byte/karakter) jika provider upstream tidak mengembalikan field usage pada respons streaming.
- Interval auto-sync kuota live di background.

## Testing Decisions
- **Seam(s)**:
  1. `src/services/usage.js` — Interface `recordUsage(params)` dan `getUsageStats(query)`.
  2. `src/services/quota.js` — Interface `syncProviderQuota(connection)` dan `getQuotaStatus(connectionId)`.
  3. `src/gateway/chat.js` & `src/gateway/messages.js` — Integrasi SSE usage tap.
- **Test Strategy**:
  - In-memory database `:memory:` untuk menguji persistensi dan agregasi query usage.
  - Mock streaming responses yang memancarkan token usage chunks untuk memverifikasi penangkapan asynchronous.
- **Environment**: Node.js 22+ local test harness.

## Out of Scope
- Algoritma pemadatan token RTK dan Caveman (bagian dari F-04).
- Tampilan grafik dan visualisasi dashboard (bagian dari F-05).
