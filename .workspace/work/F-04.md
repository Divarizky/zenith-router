# F-04 — Token Saver Engine

## Problem
Coding agents (Pi, Claude Code, Cursor) sering kali mengirimkan riwayat percakapan panjang yang memuat puluhan kilobyte log terminal, duplikasi git diff, atau pesan error berulang. Selain itu, model AI cenderung merespons dengan kalimat basa-basi dan perulangan konteks yang menghabiskan token output berharga. Hal ini memboroskan kuota akun dan memperlambat throughput respons.

## Solution
zenroute menyediakan Token Saver Engine in-process berorientasi pipeline yang mengeksekusi dua teknik optimasi:
1. **RTK (Reduced Token Kit)**: Memadatkan output tool, deduplikasi baris log berulang, dan memangkas whitespace/diff redundan di dalam pesan user dan tool result tanpa merusak substansi kode.
2. **Caveman System Compaction**: Menyisipkan instruksi efisiensi ke system prompt agar model menghasilkan jawaban teknis padat tanpa basa-basi percakapan.
Seluruh proses berjalan in-memory secara fail-open (jika gagal, request asli tetap diteruskan).

## User Stories
- (MUST) As a developer, I want repetitive terminal logs and oversized tool outputs in my prompts to be condensed, so that input token usage is reduced by 20–40%.
- (MUST) As a developer, I want an optional Caveman system prompt modifier, so that LLM output is terse, direct, and avoids conversational pleasantries.
- (MUST) As a developer, I want the token saver pipeline to be fail-open, so that any failure during compression never interrupts or breaks an outgoing request.
- (SHOULD) As a developer, I want to toggle RTK and Caveman independently via settings or request parameters.
- (NICE) As a developer, I want to see token savings metrics (tokens saved before vs after) recorded in the request metadata.

## Acceptance Criteria
- AC-01: WHEN RTK diaktifkan THEN sistem SHALL memadatkan pesan yang memuat log berulang atau tool result panjang sebelum payload dikirim ke upstream.
- AC-02: WHEN Caveman diaktifkan THEN sistem SHALL menyisipkan aturan instruksi efisiensi ke system prompt tanpa menduplikasi instruksi sistem yang sudah ada.
- AC-03: IF terjadi kegagalan atau exception pada saat proses pemadatan token THEN sistem SHALL meneruskan payload asli secara fail-open tanpa melempar HTTP error ke client.
- AC-04: WHEN RTK atau Caveman dinonaktifkan di pengaturan THEN sistem SHALL melewatkan pipeline pemadatan dan meneruskan payload tanpa modifikasi.
- AC-05: WHILE memadatkan konten teks THEN sistem SHALL mempertahankan blok kode, syntax markdown, dan data JSON terstruktur agar integritas konteks kode tetap utuh.
- AC-06: WHEN request menyertakan header atau parameter `x-zenroute-token-saver: false` THEN sistem SHALL mematikan token saver khusus untuk request tersebut.
- AC-07: WHEN proses pemadatan selesai THEN sistem SHALL menghitung estimasi jumlah karakter/token yang dihemat dan menyediakannya pada log audit.

## Implementation Decisions
**Final**:
- Eksekusi 100% in-process dalam JavaScript murni tanpa ketergantungan pada binary Python eksternal (menghindari Headroom daemon eksternal).
- Arsitektur pemadatan menggunakan prinsip fail-open dengan try-catch menyeluruh.
- Penyisipan Caveman mendukung format OpenAI (system message) dan format Anthropic (`system` parameter).

**Open**:
- Pilihan tingkat intensitas Caveman (`lite`, `normal`, `strict`).
- Aturan regex dedup khusus untuk output perintah git status dan compiler errors.

## Testing Decisions
- **Seam(s)**:
  1. `src/services/tokenSaver.js` — Fungsi `applyTokenSaver(body, format, options)`.
  2. `src/services/rtk.js` — Fungsi `compressContent(text)` dan `deduplicateLines(text)`.
  3. `src/services/caveman.js` — Fungsi `injectCavemanPrompt(systemPrompt, level)`.
- **Test Strategy**:
  - Unit tests untuk kompresi teks berulang (log, stack trace, diff).
  - Integration tests pada `handleChat` untuk memastikan request tetap berjalan normal baik saat token saver aktif maupun fail-open.
- **Environment**: Node.js 22+ local test harness.

## Out of Scope
- Proxy Python Headroom eksternal.
- Kompresi model visual atau audio multimodal.
